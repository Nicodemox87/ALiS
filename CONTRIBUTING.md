# Contributing and testing

Start with a small copy of a cloud and follow [Getting started](docs/GETTING_STARTED.txt). Test import, feature calculation/cancellation, label editing, save/reopen, model train/predict and report exports independently. Record ALiS/CloudCompare versions, input size, coordinate units, parameters and hardware. Include expected versus actual behaviour and a sanitised log in an issue.

For code changes, open an issue first when the design is substantial. Use a branch and pull request, explain the method and limitations, add focused tests, and retain GPL and third-party notices. Do not commit survey data, trained models, credentials, environments or build products. See [Building](BUILDING.md).

Scientific contributions need provenance, compatible class definitions, explicit rights to share data, independent validation and documented uncertainty. A contribution does not automatically become a certified training dataset or pretrained model.
